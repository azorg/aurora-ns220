# AGENTS.md — правила работы в репозитории aurora-ns220

Этот репозиторий — **база знаний** по исследованию планшета **NS220 (MVK-2020, Byterg)**
с ОС **Aurora** (русский форк Sailfish OS, SoC MediaTek MT6735/6737t, ARMv7).
Здесь хранятся: отчёты, артефакты прошивки, документация и код-инфраструктура
(скрипты, патчи, spec, тестовые приложения). Исходники приложений (cterm, OSK)
живут отдельно — `~/work/clear-ssh/cterm/`; сюда попадают только результаты,
обобщения и повторяемые рецепты. Крупные блобы — в `~/aurora-ns220/` (см. ниже).

Общая задача проекта — см. `TODO.txt` § «Цели».

## Структура репозитория

├── doc/                            ← документация, 00-INDEX.md — точка входа

├── patches/                        ← патчи GLFW, утилиты Wayland/EGL (glprobe и др.)

Документация перенесена из `~/work/clear-ssh/cterm/aurora` (2026.11.21) и здесь
является канонической; скрипты работы с устройством — в корне (справка: `doc/00-INDEX.md`).

## Обязанности AI-агента

1. **ChangeLog.ai** — каждое своё действие агент обязан записать в `ChangeLog.ai`
   (в корне). Формат записи (как в clear-ssh):

   ```
   ГГГГ.ММ.ДД [дн] (модель AI-ассистент, <harness>) <AI/имя>
    * <что сделано>: ...
    * <что сделано>: ...
   ```

   * записи — **новые сверху**;
   * одна запись = один смысловой шаг (что изменили/выяснили/сделали, где лежит
     результат, проверено ли);
   * запись обязана быть самодостаточной: через год по ней можно восстановить
     контекст без переписки;
   * не описывать «прочитал файлы» — только действия с результатом.

2. **doc/ai/** — длинные текстовые документы (в стиле RFC) пишутся ТОЛЬКО здесь.
   Форматы и соглашения — `doc/ai/README.md`. Типы:
   `plans/` (планы), `bugs/` (проблемы: симптом → причина → решение),
   `audit/` (чек-листы/аудиты), `notes/` (логи экспериментов), `inquiries/`
   (запросы вендорам). Короткие заметки «на полях» — в соответствующие
   существующие документы, не плодить файлы.

3. **TODO.txt** — в корне, **один актуальный план** проекта. Одна задача =
   одна строка: `[x]` сделано, `[~]` в работе, `[ ]` запланировано. После
   каждого смыслового шага агент обновляет маркеры и формулировки. Детализация
   задач — ссылками на `doc/ai/plans/*`.

4. **REPORT-*.md** — отчёт по сеансу работы с устройством. Формат: TL;DR →
   устройство → доступ → что сделали → блокировщики → артефакты → текущее
   состояние → план восстановления. Новый сеанс — новый файл, старая версия
   не правится, кроме явных опечаток.

## Факты об устройстве (всегда актуально, проверять при каждом сеансе)

| | |
|---|---|
| Модель/SoC | MVK-2020 (`aq_ns220`, плата W1C9), MT6735A/W, ARMv7, 4×A53, ~1.9 ГБ RAM |
| Serial | `INS220067941` |
| ОС | Aurora 4.0.2.340 (Balakovo), ядро 3.18.79, LVM: `sailfish-root`→`/`, `sailfish-home`→`/home` |
| Пользователь | `user` (uid 100000, `/home/user`), пароль `1234`; root-пароль `1234`, `PermitRootLogin yes` |
| Доступ | USB RNDIS: хост `192.168.2.14`, планшет **`192.168.2.15`**; Wi-Fi `192.168.1.241` (может меняться) |
| Root | `echo 1234 | devel-su sh -c '...'`; обёртки: `runroot <скрипт>`, `root_cmd.sh '<команда>'` |
| IMA | **выключен**: `boot-imaoff-v4.img` (`ima_appraise=off`, `module.sig_enforce=0`), свои бинарники/скрипты/.so запускаются |
| Brick-восстановление | MTK preloader/DA: `mtkrun.sh w <part> <image> --skipwdt` (CDC-pty bridge, handshake OK) |
| ⚠️ /home | смонтирован **noexec** — toolchain держать в `/opt`/`/tmp` или `mount -o remount,exec /home` |

## Работы с устройством — правила

* Прошивку разделов (boot/lk/...) делать ТОЛЬКО через `mtkrun.sh`
  (CDC-pty handshake), fastboot — только для `boot`/`recovery` и только если
  preloader недоступен. Перед прошивкой — бэakup разделов (`dumpall.sh`-паттерн)
  и md5 заводского образа.
* Все изменения устройства фиксировать: что прошили, md5, cmdline после,
  `/proc/cmdline`, что проверено — в ChangeLog.ai и в отчёт.
* Сеть хоста: перед ssh/скачиваниями `unset HTTP_PROXY HTTPS_PROXY` (в окружении
  есть прокси 127.0.0.1:1080, он ломает localhost-связь).
* Кэши: правка C-кода в Go-модуле (GLFW) требует `go clean -cache`
  (см. bugs/ B001).

## Крупные файлы: репозиторий vs хранилище

Этот каталог (`~/work/aurora-ns220`) **сохраняется в git как история проекта**, поэтому
он не должен содержать больших блобов: git хранит каждую версию файла навсегда, и
образы разделов/прошивки раздувают репозиторий необратимо.

| Что | Куда |
|---|---|
| Исходники, документация, скрипты, патчи, spec-файлы, небольшие артефакты (единицы/десятки КБ) | **репозиторий** `~/work/aurora-ns220` |
| Образы разделов, boot-образы, прошивки, дампы, архивы toolchain, rootfs, RPM/DEB, серии скриншотов и видео, всё > ~1 МБ | **внешнее хранилище** `~/aurora-ns220/` |

Внешнее хранилище (`~/aurora-ns220/`):

```
~/aurora-ns220/
├── bootdump/   boot-образы (stock / imaoff), дампы cmdline
├── fw/         прошивки, LK, preloader/DA
├── meta/       метаданные, логи, снимки
└── parts/      дампы разделов (dumpall.sh)
```

Правила:

* Файл > ~1 МБ — **не коммитить**, положить в `~/aurora-ns220/` и в репозитории
  оставить только ссылку на путь + контрольную сумму (`md5sum`/`sha256sum`) и
  команду/скрипт, которым он получен или собран.
* Всё, что можно воспроизвести сборкой (бинарники, `.rpm`, `.tgz`, rootfs), тоже
  держим во внешнем каталоге — в git только рецепт сборки.
* Точечные бинарные артефакты, нужные для воспроизведения и понимания (например,
  `bin/*.so` IMA/validation, `lk/lk_signoff.bin`, патчи), допустимы, пока они
  небольшие; при росте — выносить.
* Каталог `~/aurora-ns220/` бэкапить отдельно (он не в git).
* `.gitignore` в корне исключает типовые тяжёлые расширения и результаты сборки.

## Стиль

* Язык документации — русский. Код, флаги, команды — как есть.
* Документ начинается с даты и цели. Выводы — отдельно от догадок
  («проверено» vs «гипотеза»).
* Не удалять артефакты (`bin/`, `lk/`) — только добавлять. Крупное — во внешнее хранилище.
