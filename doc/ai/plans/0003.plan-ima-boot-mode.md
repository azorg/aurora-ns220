# 0003. Проверка подписи исполняемых файлов как режим загрузки (статус: в работе, 2026.11.21)

Цель: на этапе загрузки выбирать «строгий» (IMA appraisal enforce + sig_enforce=1)
или «разработческий» (off) режим, не перепрошивая boot вручную каждый раз.

Контекст: cmdline живёт в заголовке boot-образа (0x40, REPORT §19). Сейчас есть
два образа: заводской (`boot-stock-16m.img`, IMA enforce) и `boot-imaoff-v4.img`
(IMA off). Переключение — прошивкой через `mtkrun.sh`. LK умеет показывать
boot-menu (`0bb4:0afe`, выбор normal) — кандидат на переключатель.

## Приёмка

Из пользовательского пространства (или boot-menu) одной командой включается
IMA enforce и обратно, устройство грузится в обоих режимах; свои бинарники
исполняются только в dev-режиме; процедура восстановления — в doc.

## Заметки

* `lk_signoff.bin` (lk/) и `lk_signoff.zip` — артефакты подписи LK; разобрать,
  как устроена проверка (полезно для 0009).
* Secure boot: `fastboot getvar secure: yes, unlocked: no` — LK проверяет boot.
  Правка cmdline проходит потому, что подпись в заголовке `ANDROID!` не
  пересчитывается LK для этого устройства (проверено экспериментально).
