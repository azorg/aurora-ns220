# 0017. RuStore на планшете NS220 (Aurora 4.0.2.340, armv7hl) (статус: проверено — НЕВОЗМОЖНО, 2026.11.21)

Цель: понять, можно ли поставить клиент RuStore на наш планшет, и если нет —
зафиксировать точную причину и рабочие альтернативы.

## Исходные данные (наши)

| | |
|---|---|
| Устройство | MVK-2020 (NS220), MT6735A/W, **ARMv7 (32-бит)**, 1.9 ГБ RAM |
| ОС | **Aurora 4.0.2.340** (Balakovo), ядро 3.18.79 |
| Пакеты | rpm 4.16, подпись — наш GPG-ключ; валидатор OMP обходится в dev-режиме |
| IMA | выключен (`ima_appraise=off`) — свои бинарники запускаются |
| Android-рантайма | нет (Aurora — Linux/Qt, не Android) |

## Почему «просто поставить» не выйдет (гипотезы для проверки)

1. **Версия платформы.** Клиент RuStore для Aurora ориентирован на **Aurora 5**;
   в 4.0.2 другая версия Qt (5.6), другие системные библиотеки и API магазина.
   Пакет может требовать `aurora-version >= 5.x` в зависимостях.
2. **Архитектура.** Aurora 5-устройства — в основном **arm64**; наш SoC — armv7l.
   Если сборки `armv7hl` нет, пакет не установится/не запустится.
3. **Подпись и валидатор.** Официальный пакет подписан OMP; поставить можно
   (`--define '__transaction_validation %{nil}'`), но при `ima_appraise=enforce`
   он не запустится без доверенного ключа. У нас IMA off — этот пункт не блокер.
4. **Нет Android-рантайма.** Android-версия RuStore (APK) нам не подходит:
   в Aurora 4 нет Alien Dalvik/эмуляции, только нативные RPM.

## Результат проверки (2026-11-21)

**Официально:** «Официальный магазин приложений RuStore для ОС Аврора **не
поддерживается на версиях системы ниже 5.1** в связи с отсутствием компонентов
системы, необходимых для работы магазина» — справочный центр RuStore,
<https://www.rustore.ru/help/users/start/install-on-aurora>.

**Пакет есть** (32-битная сборка!): <https://static.rustore.ru/osaurora/rustore32.rpm>
(и `rustore64.rpm`), 4.0 МБ, `ru.vk.RuStore-1.7-3.armv7hl`, без подписи в файле.

**Почему не запускается на нашей 4.0.2.340** (проверено установкой в dev-режиме):

| Требование пакета | Что есть у нас |
|---|---|
| GLIBC_2.32 / 2.33 / 2.34 | glibc **2.30** (`ldd --version`) |
| GLIBCXX_3.4.29 / 3.4.30 | libstdc++ до **3.4.25** |
| `libmarket.so.0` | **отсутствует** (компонент Aurora 5) |
| `sailfish-components-webview-qt5*` | нет |
| Qt 5 (пакет собран под новый Qt) | Qt **5.6.3** (Aurora 4) |

Установка `rpm -ivh --nodeps --define '__transaction_validation %{nil}'` проходит,
но запуск сразу падает:
`error while loading shared libraries: libmarket.so.0: cannot open shared object file`.
Даже с заглушкой libmarket динамический загрузчик упрётся в отсутствие
`GLIBC_2.32+`/`GLIBCXX_3.4.29+` — это не обходится без замены glibc/libstdc++,
то есть без перехода на Aurora 5 (которой для armv7/MT6735 нет).
Пакет после проверки удалён (`rpm -e ru.vk.RuStore`), RPM сохранён вне git:
`~/aurora-ns220/build/rustore/rustore32.rpm`.

**Альтернативы:** веб-версия `rustore.ru` в штатном браузере (работает),
ручная установка Aurora-пакетов из доступных репозиториев OMP, для Android-APK —
нужен Android-рантайм, которого в Aurora 4 нет.

## Приёмка

Есть однозначный ответ: «работает/не работает», с точной причиной (версия
платформы, архитектура, подпись), ссылками на источник и, если применимо, —
рабочей инструкцией установки.

## Заметки

* Веб-версия RuStore доступна в штатном браузере Aurora уже сейчас — это
  рабочая альтернатива для скачивания APK на другие устройства, но не для
  установки приложений на сам планшет.
* Любая установка стороннего пакета — только в dev-режиме (`scripts/boot-mode dev`),
  с бэкапом разделов (см. `AGENTS.md`).
