# 0018. Читалка книг (EPUB / FB2 / PDF / DjVu) на NS220 (статус: исследование, 2026.11.21)

Вопрос: можно ли на наших наработках (Go + Fyne + GLFW/lipstick, ARMv7, 1.9 ГБ RAM,
1200×1920) сделать читалку и что взять из open source.

## Короткий ответ

Да. Разделяем движки по форматам — не надо писать рендеринг книг с нуля:

| Формат | Движок | Как встраивается | Лицензия |
|---|---|---|---|
| EPUB | чистый Go: `github.com/mdigger/epub3`/`epub` (парсинг), `golang.org/x/net/html` + `go-text/typesetting` (вёрстка) | нативно в Fyne: текст/картинки/оглавление | MIT/BSD |
| FB2 | чистый Go: `encoding/xml`/`beevik/etree` (FB2 — один XML), base64-картинки | нативно | — |
| PDF | **MuPDF** (`mupdf`/`mutool`) или **poppler** (`pdftoppm`) | CLI-рендер страницы в PNG (`mutool draw -o p%d.png`) → `canvas.Image` в Fyne; либо `go-fitz` (cgo-обёртка MuPDF) | AGPL / GPL |
| DjVu | **DjVuLibre** (`ddjvu`/`djvused`) | CLI: `ddjvu -format=png page.djvu out.png` → Fyne | GPL |

Почему CLI-рендер для PDF/DjVu — быстрый и надёжный путь на ARMv7: не тащим
C++-ABI в Fyne-процесс, рендерим страницу в файл/пайп и показываем как картинку.
Кэш 2–3 страниц вперёд/назад, предзагрузка в горутине. При 1.9 ГБ RAM страница
1200×1920 в RGBA — 9 МБ, кэш из 5 страниц = 45 МБ, нормально.

Альтернатива «взять целиком»: **KOReader** (Lua/C, умеет fb0/framebuffer, EPUB/FB2/
PDF/DjVu, огромная экосистема) — но он рисует напрямую в framebuffer и потребует
останавливать lipstick (или запуска в отдельном VT), т.е. это «второй режим
устройства», а не приложение Aurora. Для быстрого результата можно попробовать
как эксперимент, но интегрировать в Aurora-меню сложно.

## Что переиспользуем из проекта

* окно/EGL/тач/жесты/скролл/поворот — `apps/hello-ns220` (GLFW-патчи, Mali);
* крупная тема и панель — `theme.go`, `panel.go` (кнопки/шрифты/жесты);
* `-keepawake` и управление подсветкой — чтобы экран не гас во время чтения;
* `go-text/typesetting` уже в зависимостях Fyne — вёрстка с переносами и шрифтами;
* шрифты с кириллицей (DejaVu/Liberation) — есть в системе, грузим через
  `fyne.LoadFontFromFile`/`canvas.Text` c `FontSource`.

## Этапы

| | Этап | Статус |
|---|---|---|
| P0 | Просмотрщик изображений страниц + листание жестами/кнопками (каркас) | [ ] |
| P1 | EPUB: парсинг (контейнер OPF/спайн), текст + картинки, оглавление, позиция чтения | [ ] |
| P2 | FB2: XML → блоки (параграфы, заголовки, эпиграфы, картинки base64), оглавление | [ ] |
| P3 | PDF: `mutool draw` (или `pdftoppm`) → PNG → Fyne; кэш страниц, зум, ночной режим (инверсия) | [ ] |
| P4 | DjVu: `ddjvu` → PNG; тот же просмотрщик | [ ] |
| P5 | Библиотека: список книг в каталоге, обложки, поиск; хранение прогресса (JSON) | [ ] |
| P6 | Комфорт: ночная тема, размер/шрифт, поля, двухстраничный режим (ландшафт невозможен — B047), TTS (не проверено) | [ ] |
| P7 | Упаковка в RPM (рендереры — зависимости: mupdf-tools/djvulibre или собранные бинарники) | [ ] |

## Что нужно проверить на устройстве

1. Есть ли `mutool`/`pdftoppm`/`ddjvu` в OMP-репозиториях (`zypper se`) или их
   придётся собирать (у нас есть gcc; для poppler нужны зависимости).
2. Скорость рендера PDF-страницы (MuPDF на 4×A53 — ориентировочно 0.3–1.5 с;
   кэш обязателен).
3. Память/GC при больших EPUB (glibc, Go 1.27, 1.9 ГБ).
4. Читаемость шрифтов на 264 dpi (крупная тема уже помогает).

## Лицензии

MuPDF — AGPL (для внутреннего проекта ок; для распространения — коммерческая
или GPL-совместимая схема), poppler — GPL-2/3, DjVuLibre — GPL-2. Go-библиотеки —
MIT/BSD. Если планируется публикация — либо GPL-совместимая лицензия проекта,
либо замена рендереров (например, PDFium — BSD, но тяжёлый).
