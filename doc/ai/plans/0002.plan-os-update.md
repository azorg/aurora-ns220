# 0002. Обновление ОС до последней поддерживаемой версии (статус: активен, 2026.11.21)

Цель: держать на планшете максимально новую Aurora, поддерживаемую для `aq_ns220`
(MT8735A, kernel 3.18.79, adaptation-слой 249 — закрытый OMP-репо), не теряя
root/SSH/IMA-off.

Контекст: 4.0.2.249 → 4.0.2.340 сделано (793 пакета, `ssu up`, REPORT §3).
Ядро и адаптация остались 249-слоя — обновление ядра возможно только через
OMP-репозитории (нужен аккаунт/сертификат разработчика).

## Этапы

| | Этап | Статус |
|---|---|---|
| P0 | Снять текущее состояние: `ssu re`, `ssu lr`, `version`, `rpm -qa \| wc -l` | [x] |
| P1 | Обновиться до 4.0.2.340 (userland + hotfixes) | [x] |
| P2 | Проверить наличие новых релизов для устройства (ssu lr/rnd-репо, auroraos.ru, OMP SDK) — есть ли >340 и есть ли adaptation для MT8735A | [ ] |
| P3 | Если есть — обновиться, сохранив IMA-off; после обновления перепроверить `/proc/cmdline` и запуск своих бинарников | [ ] |
| P4 | Зафиксировать в REPORT новый бэкап разделов + md5 boot | [ ] |

## Приёмка

`ssu re` = последняя доступная версия; свои бинарники запускаются; UI живой;
failed units = 0; изменения записаны в ChangeLog.ai и REPORT.

## Риски

* Обновление может перезаписать `boot` (IMA off) → после `ssu up` проверять
  `/proc/cmdline`; при необходимости — повторно прошить `boot-imaoff-v4.img`.
* Смена ядра/adaptation ломает Mali/libhybris-стек (Fyne/EGL) — проверять
  `scripts/run-fyne-gpu.sh` после каждого обновления.
