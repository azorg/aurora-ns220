# 09. Тач-ввод и клавиатура (результаты замеров)

Проверено на устройстве (Aurora 4.0.2.340, lipstick), приложение — тест
`../tests/gesture-keyboard/`, GLFW с патчами `../patches/glfw-aurora.patch`.

## 9.1 Что отдаёт композитор

`wl_seat.capabilities(7)` = `POINTER | KEYBOARD | TOUCH` — все три возможности есть.
**Но** lipstick **не эмулирует мышь из тача**: при касании приходят только события
`wl_touch`, а `wl_pointer` молчит.

GLFW 3.3.x (используемый Fyne) **не умеет `wl_touch` вообще** — он запрашивает только
`get_pointer` и `get_keyboard`. Поэтому тапы «не доходили» до Fyne.

## 9.2 Патч: тач → события мыши

В `patches/glfw-aurora.patch` (файл `wl_window.c`) добавлено:

* в `_GLFWplatform`: `struct wl_touch* touch; _GLFWwindow* touchFocus; int32_t touchId;`
* в `seatHandleCapabilities()`: создание/уничтожение `wl_touch` по `WL_SEAT_CAPABILITY_TOUCH`;
* listener `wl_touch_listener`:
  * `down` → запоминаем окно по `wl_surface_get_user_data(surface)`, ставим курсор,
    `_glfwInputCursorPos()` + `_glfwInputMouseClick(LEFT, PRESS)`;
  * `motion` → `_glfwInputCursorPos()`;
  * `up` → `_glfwInputMouseClick(LEFT, RELEASE)`;
  * `cancel` → release;
  * `frame/shape/orientation` — пустые.

После патча (и **обязательной** очистки cgo-кэша: `go clean -cache`) Fyne получает:

```
MOUSE down btn=1 pos=199.6,19.2
MOUSE up   btn=1 pos=199.6,19.2
DRAG dx=-52.0 dy=79.6
DRAG end
TAP  x=199.6 y=19.2
```

То есть работают: тап, двойной тап (если два подряд), drag (свайп), и, соответственно,
`fyne.Tappable`, `fyne.Draggable`, кнопки, списки, скролл по drag.

## 9.3 Скролл двумя пальцами

`wl_touch` даёт несколько `id` (мы видели `id=1` и `id=2` одновременно). Сейчас патч
отслеживает только один палец (`touchId`), поэтому «pinch/двухпальцевый скролл» не
эмулируется. Варианты:

1. Считать два активных пальца и генерировать `_glfwInputScroll()` по вертикальному
   смещению их центра (жест «двумя пальцами»).
2. Или в самом приложении (cterm) реализовать скролл через drag по краю/полосе.

Для терминала практичнее: drag = выделение текста, а скролл — колесом/кнопками или
двумя пальцами (п.1).

## 9.4 Системная клавиатура: НЕВОЗМОЖНА

В списке Wayland-глобалов lipstick **нет** `zwp_text_input_manager_v3`, нет
`zwp_input_method` (это подтверждено `patches/wlinfo.c`). Aurora использует собственный
Qt-путь (`qt_touch_extension`/`maliit-server`) для Qt-приложений; сторонним клиентам
системная клавиатура недоступна.

Вывод: **для Fyne-приложения нужна собственная экранная клавиатура** (canvas-виджет).
Для терминала это даже удобнее, потому что можно сделать:

* раскладки **EN/RU** (переключение кнопкой, обе раскладки — привычные);
* модификаторы: `Ctrl`, `Alt`, `Esc`, `Tab`, `Shift`, стрелки, `Home/End/PgUp/PgDn`;
* комбинации (`Ctrl+C`, `Ctrl+D`, `Ctrl+Z`), историю стрелками;
* аппаратную клавиатуру (USB/BT) — она работает как обычный `wl_keyboard`
  (в логах видно `wl_keyboard.keymap/enter`), причём с системными раскладками
  (`omp-keyboard-presage-layouts-{en_us,ru_ru}` установлены).

Проверка аппаратной клавиатуры: в тесте есть поле ввода; при подключении USB/BT-клавиатуры
Fyne получает `KEY`/`CHAR` события (в логе `gk.dbg` видны `wl_keyboard` события).

## 9.5 Замечание про координаты

В логе видно расхождение: тач-координаты приходят в пикселях поверхности, а Fyne
оперирует логическими точками с учётом `FYNE_SCALE` (2.5). Например тап в пикселе
`(385, 534)` дал Fyne-координату `(162, 5.6)` — по X масштаб ~2.37 (совпадает с 2.5),
по Y — нет. Нужно проверить и, при необходимости, привести масштаб к одному:

* либо в touch-обработчике делить координаты на `window->wl.scale`/`FYNE_SCALE`;
* либо задавать GLFW content scale (тогда Fyne сам пересчитает);
* либо в приложении использовать `FYNE_SCALE=1` и увеличивать шрифты вручную.

Для cterm (позиционирование курсора/выделение) это надо довести до линейного
соответствия — это первое, что стоит проверить при разработке UI.

## 9.6 Итоги для задачи «эмулятор терминала»

| Требование | Статус |
|---|---|
| Тап / двойной тап | ✅ (после патча) |
| Drag (свайп, выделение) | ✅ |
| Скролл двумя пальцами | ⚠️ нужно реализовать (жест по двум `id`) |
| Системная клавиатура | ❌ невозможно → **своя экранная клавиатура** |
| Аппаратная клавиатура (USB/BT) | ✅ работает (`wl_keyboard`), раскладки en/ru в системе есть |
| UTF-8 ввод/вывод | ✅ (Fyne/Go — Unicode; шрифты с кириллицей в системе есть) |
| PTY-сессия | ✅ (см. ниже) |

### PTY

Для терминала нужен `forkpty`/`openpty`. В Aurora это доступно (busybox/glibc), в Go —
пакет `github.com/creack/pty` (чистый Go, работает на armv7). Проверить:

```bash
ls -l /dev/ptmx /dev/pts
```

`pkg/fyneterm/session_pty.go` в проекте ClearTERM уже использует PTY — на Aurora он
должен работать без изменений; проверить нужно только `TERM=xterm-256color` и шрифты.

## 9.7 Что делать дальше (по cterm)

1. Собрать `cterm` под Aurora (`go build -tags "wayland gles egl"` c нашим `replace`).
2. Заменить/дополнить ввод: собственная экранная клавиатура-виджет (EN/RU + модификаторы).
3. Реализовать двухпальцевый скролл в GLFW-патче (или в виджете).
4. Починить соответствие координат (п. 9.5).
5. Проверить производительность llvmpipe на полноэкранном терминале (перерисовка при
   выводе текста) — при необходимости ограничить частоту кадров.


## 9.6. Двухпальцевая прокрутка (патч GLFW v3.4, 2026-11-21)

lipstick отдаёт `wl_touch` с несколькими `id`; наш первый патч
(`glfw-aurora.patch`) превращал **один** палец в мышь, остальные игнорировал.
Прокрутка двумя пальцами реализована в GLFW отдельным патчем
`patches/patch_glfw_scroll.py` (маркер `AURORA_TOUCH_SCROLL_V2`, применяется
поверх уже пропатченного `go-glfw34`):

* 1 палец — как раньше: курсор + левая кнопка (тап, свайп, drag);
* появление второго пальца **отпускает** «нажатую» кнопку (случайный клик не
  возникает) и включает режим прокрутки;
* в движении считается средняя точка двух пальцев; если |dy| > |dx|, смещение
  накапливается, а в `touchHandleFrame` (раз в кадр) выдаётся одно событие
  `_glfwInputScroll(window, 0, -accum*0.6)` — так UI-поток Fyne не заваливается
  событиями;
* снятие любого пальца завершает прокрутку (лишних кликов нет), одиночное
  касание снова работает как мышь.

Коэффициент 0.6 подобран под Fyne (1 «щелчок» ≈ 16 px прокрутки); при
необходимости меняется в патче. Проверка: приложение `apps/hello-ns220` **видимо реагирует** на прокрутку —
справа появляется полоса с «ползунком», в HUD растёт «жест: прокрутка dy=… ·
прокрутка всего: …», у точки касания вспыхивает зелёное «⇅ …», счётчик «скролл»
увеличивается. Сам жест нужно делать пальцами (синтетически `wl_touch` не
подделать — нет `/dev/uinput`), но в `-selftest` прокрутка инжектируется и
индикация проверяется по снимку.
